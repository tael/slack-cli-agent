# 단계 계획과 실행 (2026-11-28 소유자 지시)

요청을 받으면 쓸 수 있는 스킬·도구 목록으로 작은 단계를 계획하고, 단계를 차례로 실행한다.
결정 : 1A 계획은 메인, 실행은 executor 작업자 / 2A Playwright 별도 프로필 / 3A 키체인 /
4A 결제·발송·삭제만 승인 / 5A 진행 카드 한 장 / 6A 실패 시 재계획, 상한 2회 / 7B 모든 요청.

## 흐름

    UserPromptSubmit  plan_start   스킬 목록(SCA_PLAN_SKILLS)과 도구 목록(SCA_PLAN_SOURCES)을 계획 호출에 넣고
                                   steps 를 받아 <transcript>.plan.steps.json 장부에 쓴다
    PreToolUse        plan_gate    갈래 계획과 함께 단계 목록·장부 명령을 한 번 주입한다
                      plan_steps --gate  승인 단계 앞에서 도구를 막는다
    실행              executor     start N → 한 동작 → done N. 실패면 fail N 사유 → 재계획 출력
    진행 표시         progress_hook 실행 중 단계를 "2/8 로그인" 으로 카드에 쓴다

조회 1-2회 요청은 steps 가 빈 배열이라 장부가 생기지 않고 기존 흐름 그대로다.

## 승인은 코드가 막는다

- `start` 는 승인 안 된 승인 단계를 거부한다
- `approve` 는 장부를 만든 턴과 소유자 아닌 턴에서 거부한다. 승인 단계에 닿은 턴은 반드시 답을 끝내고 묻는다
- 게이트는 그 턴에서 승인 단계가 다음 차례면 읽기 외 도구를 막는다
- 게이트는 승인 기록이 없으면 브라우저 스킬의 `--approved` 를 모든 턴에서 막는다
- 브라우저 스킬은 결제·주문·송금·삭제·발송류 버튼을 `--approved` 없이 누르지 않는다

새 요청이 오면 끝난 장부는 지운다. 승인 대기 장부는 새 계획에 단계가 없을 때 남긴다("승인" 같은 짧은 답).

## 스킬 (운영물, ~/.asuka/skills/installed)

- browser : Playwright 크로미움, CDP 9333 으로 호출 사이에 유지. 요소 ref, iframe, 대화상자, 새 탭, 키체인 비밀값 입력
- vault : 키체인 항목 이름 목록. 값은 출력하지 않는다
