# 진행 표시 - 엔진별 자리 (sca-8ks)

사람이 보는 문구는 엔진이 달라도 같다. 다른 것은 도구 이름이 어디에 오는가와
그것을 누가 쓰는가다.

    엔진      쓰는 쪽                     도구 이름 자리
    claude   훅 프로세스(progress_hook)   훅 payload 의 tool_name
    codex    실행기(engine/stream.py)     item.started/item.completed 의 item.type
    gemini   실행기(engine/stream.py)     step_update.tool_name (step_type=="tool")

`Engine.streams_progress` 가 갈림길이다. 참이면 실행기가 stdout 을 줄 단위로
읽어 `progress_tool_name()` 에 넘기고, 거짓이면 그 엔진이 다른 방법으로 쓴다.
**클로드를 참으로 바꾸면 안 된다** - 훅과 실행기가 같은 파일에 쓰게 돼 호출
하나가 두 번 기록된다.

## 실측 (2026-09-19)

codex 에서 나온 item.type - `command_execution`, `file_change`, `web_search`,
`agent_message`. 파일 읽기도 `command_execution` 이다(rg·sed 를 셸로 부른다).
`error` 는 parse 가 이미 쓰고 있고 도구가 아니다.

agy 의 도구 이름은 `init` 이벤트의 `tools` 에 전부 들어 있다. 56개다. 추측할
필요가 없으므로 표에 넣을 이름은 거기서 가져온다.

**이름 표는 접두어 앞선 것이 이긴다**(`ToolLabelMapper`). `browser_subagent` 를
`browser_` 뒤에 두면 브라우저 문구로 덮인다. agy 이름을 더할 때 이 순서를 본다.

## 확인한 경로

    codex    아스카 프로필과 아스카 venv 로 실행 - "명령 실행 중", "답 쓰는 중"
    gemini   stream-json 으로 실행 - 답·세션 ID·사용량·소요시간이 그대로 나오고
             진행 로그에 run_command 가 기록됐다

표에 없는 이름은 "확인하는 중" 으로 나간다. 답이 안 나가는 것이 아니라 문구만
뭉뚱그려진다. 새 도구가 보이면 표에 더한다.
