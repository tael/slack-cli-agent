# 에이전트를 하나 추가할 때 필요한 입력 정보

봇 하나를 새로 붙이려면 무엇을 미리 정해야 하고 무엇을 슬랙에서 받아와야 하는지
정리한 것이다. 실제 절차와 함정은 [실테스트-아스카.md](실테스트-아스카.md) 에 있다.

소유자·채널·워크스페이스는 `tools/new-bot.sh` 가 환경변수로 받고 기본값을
두지 않는다(`BOT_OWNER_USER_ID`, `BOT_TROUBLESHOOT_CHANNEL`, `BOT_WORKSPACE`).
조직 고유값이라 스크립트가 임의로 정하면 안 된다. 후보는
`tools/detect-defaults.py` 가 지금 환경에서 찾아 보여준다 — 설정 토큰이 있는
워크스페이스와, 이미 있는 봇이 쓰는 소유자·채널이다. 값을 정하는 것은 사람이고,
도구는 후보만 낸다.

## 1. 사람이 정해야 하는 값

이것이 없으면 시작할 수 없다. 나머지는 여기서 파생된다.

| 값 | 예 | 쓰이는 곳 | 비고 |
|---|---|---|---|
| 표시 이름 | 아스카 | 앱 이름, 봇 표시명, 프로필 `display_name` | 한글 가능 |
| ASCII 이름 | asuka | 봇 기본명, 프로필 `name`, 상태 디렉터리 | 한글 불가 |
| 한 줄 설명 | 로컬 지식으로 답하는 읽기 전용 에이전트 | 앱 설명 | |
| 아이콘 | 512px 정사각 PNG | 앱 아이콘 | 안 주면 `src/slack_cli_agent/assets/default-bot-icon.png` 를 쓴다 |
| 워크스페이스 | tael | 앱 생성·설치 | 회사 워크스페이스와 섞지 않는다 |
| 소유자 | U0EXAMPLE07 | 프로필 `owner_user_id` | 소유자 전용 권한 판정에 쓴다 |
| 담당 채널 | C0EXAMPLE01 | `channels.json`, `troubleshoot_channel` | 채널마다 모드·모델을 따로 준다 |
| 엔진 | codex | 프로필 `primary_engine.type` | claude 또는 codex |
| 모델 | gpt-5.6-luna | 프로필 `primary_engine.model` | 소유자용 모델을 따로 줄 수 있다 |
| 샌드박스 | read-only | `primary_engine.options.sandbox` | 쓰기가 필요하면 workspace-write |
| 상태 디렉터리 | `~/.asuka` | 프로필 `state_dir` | 봇마다 완전히 가른다 |
| 작업 디렉터리 | `/Users/Shared/asuka-work` | 프로필 `work_root` | **홈 밖이어야 한다.** 사전 점검이 막는다 |
| 성격 | `<상태>/persona/PERSONA.md` | 프롬프트 | **여기에 이름을 안 적으면 봇이 자기 이름을 모른다** |

## 2. 슬랙에서 받아오는 값

만들면서 생기는 것이다. 미리 정할 수 없다.

| 값 | 어디서 | 저장 위치 |
|---|---|---|
| 앱 ID | 앱 생성 결과 URL | 문서에만 적어 두면 된다 |
| 봇 사용자 ID | `auth.test` 의 `user_id` | 멘션 시험에 쓴다 |
| 봇 토큰 xoxb | `/oauth` 페이지 | `<상태>/.slack_bot_token` (600) |
| 앱 토큰 xapp | Basic Information → Generate Token and Scopes | `<상태>/.slack_app_token` (600) |
| 채널 ID | `conversations.list` | `channels.json` |

**토큰은 설치물에 들어가면 안 된다.** 상태 디렉터리에 600 으로 두고 기동
스크립트가 읽어 환경변수로 넘긴다.

## 3. 매니페스트에 넣을 것

### 스코프

    듣기    app_mentions:read · channels:history · groups:history · im:history
            mpim:history · reactions:read
    알기    channels:read · groups:read · im:read · mpim:read · users:read
            users.profile:read · usergroups:read · team:read · emoji:read · files:read
    말하기  chat:write · chat:write.customize · chat:write.public · reactions:write
            files:write · im:write · channels:join

에이전트로 등록하면 `assistant:write` 가 자동으로 붙는다.

### 이벤트

    app_mention · message.channels · message.groups · message.im
    message.mpim · reaction_added

### 설정

    socket_mode_enabled      true
    interactivity            false
    org_deploy_enabled       false
    token_rotation_enabled   false

## 4. 에이전트로 등록하기

Agents 페이지(`/apps/<APP>/app-assistant`)의 **Agent experience** 를 켠다.
켜면 슬랙이 `assistant:write` 를 붙이고, 상단바 진입점과 나란히 보기 화면을 연다.

**스코프가 늘었으므로 재설치해야 반영된다.** 재설치하면 봇 토큰이 새로 나오므로
상태 디렉터리의 토큰 파일을 다시 쓴다.

같은 화면의 **Slack MCP Server** 토글은 다른 기능이다. 슬랙이 제공하는 MCP 서버에
이 앱을 붙이는 것이고, 봇이 자기 MCP 서버를 쓰는 것과 무관하다.

## 5. 이름을 바꿀 때 무엇이 언제 반영되는가

실측으로 확인한 것이다.

| 바꾼 것 | 반영 시점 |
|---|---|
| 앱 이름 | 저장 즉시 |
| 봇 표시명 | 저장 즉시. `bots.info.name`, `users.info` 의 `real_name` |
| 아이콘 | `/general` 에서 파일을 넣으면 자동 저장 |
| 스코프 | 재설치해야 반영 |
| `users.info` 의 `name` | **제거 후 다시 설치해야 바뀐다.** 재설치만으로는 안 바뀐다 |

`name` 은 슬랙이 폐기 예정으로 둔 옛 핸들이고 화면 표시에는 안 쓰인다. 값을
맞추려면 워크스페이스에서 앱을 제거하고 다시 설치한다. 제거하면 채널 참여가
풀리므로 `conversations.join` 으로 다시 넣는다.

## 6. 기동 전 확인

    slack-cli-agent preflight --profile <이름> --profile-dir <경로>

"기동 가능" 이 나와야 한다. 흔한 실패는 작업 디렉터리가 홈 안에 있는 것이다.

엔진이 codex 면 격리 홈(`primary_engine.home_dir`)에 `auth.json` 이 있어야 한다.
새 홈에는 로그인 정보가 없어 그대로는 안 돈다.
