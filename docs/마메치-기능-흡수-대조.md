## 대조 방법

```sh
grep -nE "^(def|class) " bot.py | sed 's/(.*//' | awk '{print $2}' > /tmp/orig_names.txt
```

다시 본다 — 이 저장소는 OOP 로 다시 쓰면서 이름이 대부분 바뀌었다. 예로 원본의

## 미흡수 — 확인된 것 없음. 다만 아직 입증되지 않았다

전수 대조가 안 끝났다. 2026-09-19 재대조에서 이름 미매치 115개 중 16개만
기능으로 확인했고, 표본 검사는 "전부 흡수" 의 증명이 못 된다. 나머지의

아래는 이전에 미흡수로 올라 있던 것이고 전부 닫혔다. 옮겨간 자리를 남긴다.

## 다시 대조할 때

이 표를 갱신한다. 새로 만든 이슈는 표의 "미흡수" 절에서 지우고 "흡수된 것" 으로
옮긴다. 원본이 갱신되면 대조 명령을 다시 돌린다.

**"나머지는 전부 헬퍼" 로 끝내지 않는다.** 표본 검사는 "전부 흡수" 의 증명이
못 된다. 미매치를 전부 훑되, 이름이 아니라 **원본의 docstring 을 읽어** 판정한다.
외부에서 관찰되는 것부터 본다 — 권한·프롬프트·엔진 전환·이벤트 진입·영속화·
재시작 복구·슬랙 호출·사용자 출력·상태 변경. 순수 문자열 변환과 조회 보조가
뒤다.

    cd /Users/example/Projects/mametchi-slack-bot
    grep -nE "^(def|class) " bot.py | sed 's/(.*//' | awk '{print $2}' \
      | sed 's/:$//' | sort -u > /tmp/orig.txt
    cd /Users/example/Jobs/slack-cli-agent
    python3 -c "
    import pathlib
    orig = [l.strip() for l in open('/tmp/orig.txt') if l.strip()]
    blob = '\n'.join(p.read_text(errors='ignore') for p in pathlib.Path('src').rglob('*.py'))
    print('\n'.join(n for n in orig if n not in blob))"

이름 하나씩 `grep -r` 로 도는 방식은 208회 실행이라 2분을 넘긴다. 위처럼
한 번 읽어 메모리에서 대조한다.

**기능으로 2차 대조할 때는 이름이 아니라 그 일을 뭐라고 부르는지로 찾는다.**
이 저장소는 이름을 거의 다 바꿨으므로, 원본 docstring 의 서술어를 검색어로
쓴다(예로 "다른 봇", "화자", "남겨둔 보고").

**그 검색이 못 잡는 자리가 둘이다.**

    조직 고유값을 뺀 기능    원본 낱말이 여기엔 아예 없다
    이름이 주석·문자열에만   매치가 나와도 구현이 아니다

전자로 2026-09-19 에 오판했다. `drop_vooster` 를 "텔레메트리"·"vooster" 로
찾다가 미흡수로 적었으나, 실제로는 `guard/dropline.py` 에 그대로 있었다.
이 저장소가 규칙에 따라 그 낱말을 일부러 뺀 것이 원인이다. **원본에 조직
이름·제품명이 든 함수는 그 낱말을 지우고 남는 동작의 형태로 찾는다** — 이
경우 "줄 단위로 지운다" 였다. 후자는 매치가 나오면 그 파일을 열어 확인한다.

**구현이 있는 것으로 끝내지 않는다.** 모든 엔진·재시도·출력 경로에서 실제로
그것을 지나는지 본다. 원본 커밋과 이 저장소 커밋을 함께 적어 대조 시점을
고정한다.
