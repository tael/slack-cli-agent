# 지침 예산

시스템 지침 전체에 바이트 상한을 둔다. 이 문서는 그 값이 어디서 나왔는지를
적은 것이다. **관측된 지침 크기 분포에서 정하지 않는다** — 오독과 팽창을
거르려고 만든 기준을 그 팽창이 든 자료로 정하면 아무것도 안 걸러진다.

## 왜 상한이 필요한가

codex 와 gemini 는 재개 턴마다 시스템 지침 전체를 user prompt 에 다시 싣는다
(`engine/codex.py` 의 `_resume_prompt`, `engine/gemini.py`). 스레드 하나에서
N 번 재개하면 지침 크기 K 를 N 번 낸다. claude 는 CLI 가 지침을 따로 받아
해당이 없다.

2026-09-19 실측(asuka/codex) — 재개 1턴에 지침 7936바이트가 다시 실렸다.

## 상한을 어디에 두는가

`SystemPromptComposer` 다. 조합기만이 모든 섹션의 우선순위와 최종 본문을 안다.
`KnowledgeLoader` 에만 두면 페르소나와 앞으로 추가될 섹션이 상한 밖에 남고,
엔진 직전에서 자르면 이미 조합된 의미 구조를 잃는다.

## 무엇부터 빼는가

1. **줄일 수 없는 것** — 권한, 민감정보 보호, 침묵 규칙, 출력 형식
2. **이번 요청의 정확성** — 채널 모드, 화자와 참여자, 신뢰 수준
3. **정체성** — 페르소나, 내부 도메인 사실
4. **선택 지식** — 채널 지식, 조건 일치 지식, 학습 지식

4번만 뺀다. 1에서 3까지로 예산을 넘으면 그것은 구성 오류이지 요청 시점에
조용히 버릴 일이 아니다. 그 경우 경고를 남기고 선택 지식을 전부 뺀다.

자르는 단위는 파일 하나다. 문자 수로 중간을 끊으면 조건과 예외가 규칙에서
떨어져 나가 지침의 뜻이 바뀐다.

뺀 파일은 `BUDGET_OMITTED_HEADER` 로 알린다. 낱말이 안 맞아 안 실은 것을
알리는 `_SKIPPED_HEADER` 와 다른 헤더를 쓴다 — 자리가 없어 못 실은 파일을
"요청 낱말과 맞지 않는다" 고 말하면 모델에게 거짓을 말하는 것이 된다.

## 값을 어떻게 구했는가

정적 계약에서 도출한다.

    지원하는 엔진 중 가장 작은 확인된 컨텍스트     128K 토큰
    한국어 UTF-8 의 보수적 환산                 1 토큰당 1.5 바이트
    그 컨텍스트가 담는 바이트                    약 192KB

여기서 반드시 남겨야 할 몫을 뺀다.

    응답과 도구 호출                            절반
    대화 이력 (history_max_chars=12000 자)       약 36KB
    이번 사용자 입력과 도구 결과                  약 20KB

남는 몫이 약 40KB 다. 여기에 안전 여유를 두어 **32768 바이트(32KiB)** 를
지침 예산으로 정한다.

엔진마다 다르게 두지 않는다. 같은 채널의 같은 요청이 엔진 전환만으로 다른
지침을 받으면 "동일 로직으로 핸들링" 이 깨진다. 재전송 비용 차이는 엔진
어댑터와 `PayloadFootprint` 의 transport·replay 필드에서 다룬다.

## 이 값을 언제 다시 정하는가

지원 엔진의 최소 컨텍스트가 바뀔 때, `history_max_chars` 를 바꿀 때, 줄일 수
없는 섹션이 늘어 위 경고가 실제로 나올 때다. 관측된 지침 크기가 커졌다는
것은 다시 정할 사유가 아니다 — 그때 해야 할 일은 지식 파일을 줄이는 것이다.
