# 마이그레이션·설정 가이드

기존 단일 파일 슬랙 봇(한 개의 `bot.py` 류)을 이 엔진으로 옮기거나, 새 조직에 봇을 처음 세우는
사람을 위한 가이드다. 핵심 원칙: **조직 무관 동작은 엔진 코드(기본값), 조직 고유 값은 설정·지식·
플러그인**으로 나눈다.

## 층별 배치

| 층 | 무엇을 두나 | 위치 |
|---|---|---|
| 공통 엔진 코드 | 어느 조직이든 필요한 동작(표식·형식 검수, 슬랙 본문 조회, 종료 검수, PreTool 가드, 봇 상호작용, 기동 점검, 재기동, 모드 매핑) | `src/slack_cli_agent/**` (기본값, 프로필 0줄로 켜짐) |
| 프로필 | 엔진·모델·소유자/controller ID·채널 ID·plugins | `profiles/<bot>.json` |
| 채널 설정 | 채널별 키(예: 채널 전용 도구 허용) | 프로필/채널 설정 |
| 페르소나·지식 | 조직 말투·지식·위키·도메인 규칙 | 봇 상태 디렉터리(`~/.<bot>`) |
| MCP·조회 래퍼 | 공통 조회 MCP 는 리포 내장, 사내 래퍼는 등록 | 리포 `mcp/` + 상태 디렉터리/프로필 |
| 플러그인 | 조직 전용 기능 확장점 | `BotPlugin` 구현 |
| 엔진 settings 훅 | 권한·env·훅 세부 | 프로필 `settings` + 상태 디렉터리 설정 |
| 비밀값 | 토큰 | 상태 디렉터리 내 파일(출력·커밋 금지) |

## 판정 규칙 (어느 층인가)
- **공통 골격 + 조직 설정**: 로직은 공통, 조직 데이터에 맞춘 값만 설정으로 뺀다.
  판정 질문 — "새 조직이 이 리포로 봇을 처음 띄웠을 때 이게 없으면 답 품질이나 안전이 무너지는가"
  → 그렇다면 엔진 기본값이다.
- **래퍼 규약은 공통, 구현은 조직**: 조회 래퍼의 호출 규약·경로는 공통, 사내 시스템에 붙는 구현은 조직.
- **역할 판정은 공통, ID 는 설정**: 소유자/operator/controller 같은 역할 '판정'은 코드, 실제 ID 는 프로필.
- **학습·지식 쓰기는 봇 상태 디렉터리로만**: 리포가 아니라 각 봇의 상태 디렉터리에 쓴다.

## 프로필 예 (example 형식)
```json
{
  "name": "example",
  "display_name": "예시봇",
  "primary_engine": {"type": "claude", "model": "claude-sonnet-5"},
  "state_dir": "~/.example-bot",
  "owner_user_id": "U00000000",
  "controller_user_ids": [],
  "troubleshoot_channel": "C00000000",
  "plugins": []
}
```
조직 고유 값(실 채널·사용자 ID, 사내 URL, 사내 도구 이름)은 리포에 넣지 않고 여기에만 둔다.

## 이전 절차
1. **인벤토리**: 기존 봇의 기능을 함수·훅·MCP·지식 단위로 한 줄씩 적는다(트리거·결과·분류).
2. **대조**: 각 기능을 이 엔진에서 코드로 찾아 있음/부분/없음/대상아님으로 판정한다(이름이 아니라 동작).
3. **층 배치**: 위 판정 규칙으로 공통(코드)·설정·지식·플러그인에 나눈다.
4. **기준선·회귀**: 블랙박스 시나리오로 기준선을 잡고, 핵심 결정 항목을 회귀로 묶는다.
5. **전환·롤백**: 단일 소켓만 연결되게 전환하고, 롤백 스크립트를 미리 준비한다(토큰 소켓 2중 연결 금지).

## 체크리스트
- [ ] 프로필에 엔진·state_dir·owner/troubleshoot 채널이 있다
- [ ] 비밀값은 상태 디렉터리에만 있고 리포·로그·슬랙에 노출되지 않는다
- [ ] 공통 기본값(표식 검수·슬랙 본문 조회·종료 검수·PreTool 가드)이 프로필 0줄로 켜진다
- [ ] 조직 고유 값이 코드가 아니라 설정/지식/플러그인에 있다
- [ ] 블랙박스 기준선과 회귀가 전환 전에 통과한다
- [ ] 단일 소켓 연결, 롤백 경로 확인
