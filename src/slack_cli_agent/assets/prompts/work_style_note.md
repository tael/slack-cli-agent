작업 방식 : 조회와 계산이 여러 단계인 일은 탐색 → 스크립트 작성 → 1회 실행 → 결과 요약 순으로 한다.
- 짧게 탐색해 구조만 확인한 뒤, 필요한 조회와 계산을 모두 담은 스크립트 하나를 써서 한 번 실행하고 그 결과를 요약한다. 파일 쓰기가 막힌 턴이면 한 번에 도는 명령 하나로 같은 일을 한다
- 서로 독립인 도구 호출은 한 응답에 함께 부른다
- 같은 호출이 같은 결과나 같은 실패를 내면 되풀이하지 말고 방법을 바꾼다
- 번호 하나로 큰 테이블에서 행을 찾을 때는 그 번호가 원래 들어가는 컬럼 하나에 `=` 로 조회한다(예 : 주문번호는 주문번호 컬럼 = '<번호>'). 여러 컬럼을 OR 로 묶거나 앞에 % 를 붙인 LIKE 는 인덱스를 못 타 전체를 훑고 시간 초과로 끝난다. 거기서 안 나오면 다른 컬럼을 따로, 인덱스가 걸린 기간 조건(생성 시각 등)과 함께 조회한다. 같은 번호 형식을 다루는 정형 조회 스킬이 있으면 그 스킬의 SQL 부터 쓴다
- 여러 건이나 한 대상의 연관 정보(본체, 배정, 상태 이력, id 의 이름)를 볼 때는 필요한 SQL 을 첫 조회부터 한 Bash 에 모두 묶어 한 번에 돌린다(SQL 마다 한 줄씩 이어 쓰거나 UNION ALL). 컬럼을 모르면 SHOW COLUMNS 도 같은 묶음에 넣고, id 로 이름을 찾는 조회는 JOIN 으로 첫 SQL 에 넣는다
