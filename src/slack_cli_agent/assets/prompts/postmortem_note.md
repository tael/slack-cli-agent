현재 작업은 사후 분석이다. 이 봇이 작성한 답변 하나에 사용자가 오류를 제기했다.

준수 사항
- 수정하지 않는다. 파일을 수정하거나 명령을 실행하지 않는다
- 원인 규명과 개선안 도출까지만 수행한다. 실제 수정은 별도로 결정한다
- 오류를 정당화하지 않는다. 발생한 오류를 객관적으로 서술한다
- 추측으로 원인을 서술하지 않는다. 지침과 코드 파일을 직접 확인해 근거를 찾는다

원인 분석 방향
- 이 작업은 단일 답변에 대한 사후 분석이다. 도구나 권한 제약을 원인으로
  단정하지 않는다. 답변을 생성한 특정 지침과 절을 지목한다
- 도구나 권한 제약이 실제 원인이면 제한된 요소와 방식을 구체적으로 서술하고,
  해제 방법도 함께 서술한다

형식
출력은 두 부분으로 구성한다. 두 부분 사이에 `===상세===` 텍스트만 포함한 줄을
넣는다. 머리말 제목과 실행 정보 표는 게시 코드가 붙이므로 직접 쓰지 않는다.

전반부는 요약이다. 제목을 달지 않고 세 문장 이내로 쓴다. 무엇이 틀렸는지,
무엇이 그렇게 만들었는지, 무엇을 고칠지를 각각 한 문장으로 쓴다.

후반부는 상세다. 아래 제목을 이 순서로 그대로 쓰고 제목과 제목 사이에 `---`
구분선을 한 줄 넣는다. 해당 사항이 없는 항목도 빼지 않고 "해당 없음" 이라고
적는다.

    ## 지적받은 내용
    ## 답변이 만들어진 경위
    ## 원인
    ## 지금 형식으로 못 막는 것
    ## 고칠 대상

서술은 각 제목 아래 두 문장까지만 쓴다. 나머지는 불릿과 표로 낸다.

- 지적받은 내용 : 사용자가 지적한 것과 실제 답변 내용을 불릿으로 대조한다
- 답변이 만들어진 경위 : 시각 순서가 있으면 `| 시각 | 무엇을 했나 |` 표로 낸다
- 원인 : `| 원인 | 근거 위치 |` 표로 내고 근거 위치는 파일명과 함수명 또는
  지침 문서의 절 제목으로 적는다. 추정이면 그 행에 추정이라고 적는다
- 지금 형식으로 못 막는 것 : 이번 지침과 코드로는 검출되지 않는 경우를 불릿으로 적는다
- 고칠 대상 : `| 대상 | 파일 | 바꿀 내용 |` 표로 낸다. 실제 수정은 하지 않는다
